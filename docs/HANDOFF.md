## สิ่งที่ทำแล้ว

- ลูกค้า Login และอ่านงานของบริษัทตนเอง; RLS แยกข้อมูล และเซิร์ฟเวอร์ตรวจบทบาทจากฐานข้อมูล
- Admin จัดการลูกค้า งาน และสถานะทั้ง 15 ขั้นตอน พร้อมวันที่และหมายเหตุ
- หน้า “ผู้ดูแลระบบ” เพิ่ม/แก้ไข Admin ตั้งรหัสผ่านใหม่ เปิด/ปิดบัญชี พร้อมป้องกันปิดบัญชีตนเองหรือ Admin คนสุดท้าย
- ระบบจริงไม่แสดงรหัสผ่านเดิม; รหัสผ่านใหม่อย่างน้อย 12 ตัวอักษร ใช้อีเมลภายใน `<username>@oss-portal.invalid` จึงยังไม่มี recovery ผ่านอีเมล
- ดีไซน์ที่ผู้ใช้เลือกและเผยแพร่ครั้งล่าสุดคือ **Metro Focus**: เมนูด้านบน วงแหวนความคืบหน้า แผนผังแยกโรงงาน/Lab ธีมสว่าง ขั้นตอนรอหรือยังไม่เริ่มสีเทา
- `AGENTS.md` และคู่มือการรับช่วงใช้ร่วมได้โดยไม่ผูกกับ vendor ของ agent

## หลักฐานตรวจครั้งล่าสุด

รอบ Metro Focus ผ่าน `npm test` 10 รายการและ `npm run build` ตรวจเว็บที่เผยแพร่ผ่าน browser ที่ desktop 1440×900 และ mobile 390×844: ขั้นตอน 15 จุด เส้นเชื่อม 15 เส้น หน้าไม่ล้นแนวนอน และกด B2 เพื่ออ่านรายละเอียดในมุมมองลูกค้าได้ นี่เป็นผลรอบก่อนหน้า ไม่ใช่การรับรองทุกการเปลี่ยนแปลงในอนาคต

ภาพและข้อมูลเข้าใช้ใน `outputs/` รวมถึงเครื่องมือชั่วคราวใน `work/` ไม่ขึ้น Git ผู้รับช่วงจาก clone ใหม่ต้องไม่ถือว่าไฟล์เหล่านี้มีอยู่ คำสั่งมาตรฐานที่อยู่ใน repo อยู่ใน `package.json` และ `scripts/`

## ข้อจำกัดและงานที่ยังไม่ได้อนุมัติให้เริ่ม

ยังไม่มีไฟล์แนบ การแจ้งเตือน ประวัติผู้แก้ไขรายรายการ recovery ผ่านอีเมล หรือหน้าคืนรายการที่เก็บเข้าประวัติ ยังต้องกำหนดวิธีสำรอง/กู้คืนและทบทวนความพร้อมก่อนรับลูกค้าจริง รายการนี้เป็นบริบท ไม่ใช่คำสั่งให้ agent ทำทั้งหมด

การเลือก Soft Minimal ในตัวอย่างเปรียบเทียบครั้งล่าสุดยังไม่มีข้อความสั่งปรับเว็บ จึงคง Metro Focus ไว้จนผู้ใช้ระบุให้เปลี่ยน

โฟลเดอร์ `Diagram/` เป็นงานที่มีอยู่แบบ untracked ตอนเริ่มรอบเอกสารนี้ ไม่ได้รวมเข้า commit เอกสารและไม่ควรลบหรือเพิ่มโดยอัตโนมัติ
