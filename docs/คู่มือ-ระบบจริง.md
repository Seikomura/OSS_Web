# คู่มือ OSS Client Portal บน Vercel + Supabase

## เริ่มทดลอง

เปิดเว็บที่ Vercel แล้วใช้ข้อมูลจากไฟล์ส่วนตัว `outputs/initial-access.txt` ในเครื่องเจ้าของโปรเจกต์ มีบัญชี Admin และลูกค้าทดสอบ `demo_siam`, `demo_northstar` แต่ละลูกค้าเห็นงานของบริษัทตนเอง

หน้า Admin > บัญชีลูกค้า เพิ่มลูกค้าใหม่ กรอกบริษัท ชื่อผู้ใช้ และรหัสผ่านอย่างน้อย 12 ตัวอักษร จากนั้นเพิ่มงานให้ลูกค้ารายนั้น หน้าอัปเดตสถานะให้เลือกขั้นตอน กรอกสถานะ วันที่ และหมายเหตุ แล้วบันทึก ลูกค้าจะเห็นข้อมูลจากฐานข้อมูลเดียวกัน

การแก้บัญชีเดิมให้เว้นช่องรหัสผ่านใหม่ไว้เพื่อใช้รหัสเดิม ไม่มีการแสดงรหัสผ่านเดิมจากฐานข้อมูล ปุ่มแสดง/ซ่อนมีไว้ตรวจข้อความรหัสใหม่ที่กำลังกรอก

## บัญชีและสิทธิ์

Supabase Auth เก็บข้อมูลการยืนยันตัวตน เซิร์ฟเวอร์ตรวจผู้ใช้กับ Supabase ทุกครั้งและอ่านบทบาทจากตารางโปรไฟล์ ไม่เชื่อบทบาทที่ส่งจากหน้าเว็บหรือ metadata ที่ผู้ใช้แก้เองได้

RLS ของฐานข้อมูลแยกงานตามเจ้าของบัญชี ลูกค้าอ่านได้อย่างเดียว Admin แก้สถานะและสร้างงานได้ การสร้าง/ตั้งรหัสผ่านลูกค้าทำบนเซิร์ฟเวอร์ผ่านคีย์ที่ไม่ส่งไปยังเบราว์เซอร์ Session อยู่ใน cookie แบบ HttpOnly

ปิดใช้งานบัญชีจะหยุดการอ่านข้อมูลและการ Login การลบบัญชีหรือการลบงานในหน้าจอเป็นการเก็บเข้าประวัติ เพื่อรักษางานและประวัติ ไม่ได้ลบถาวร การคืนรายการที่เก็บเข้าประวัติยังต้องให้ผู้ดูแลฐานข้อมูลแก้ค่า `archived_at` และ `active` ยังไม่มีปุ่มคืนรายการในหน้า Admin

## ข้อมูลจาก Demo รุ่นเดิม

ข้อมูล Demo Sites อยู่ในเบราว์เซอร์แต่ละเครื่อง ส่วนระบบนี้ใช้ Supabase ไม่ได้ย้ายข้อมูลหรือบัญชีใน localStorage ของ Demo อัตโนมัติ ต้องนำข้อมูลจริงเข้าระบบใหม่ผ่าน Admin หรือจัดทำการนำเข้าจากไฟล์ที่ผู้ใช้ส่งให้ และกำหนดรหัสผ่านใหม่

ไฟล์ `dist/` และคู่มือ Demo เป็นข้อมูลของรุ่นทดลองเก่า โค้ดที่ Vercel ใช้งานมาจาก `src/`, `api/`, `server/` และ build ใหม่ทุกครั้ง
