# OSS_Web

Demo ระบบติดตามงานขออนุญาต มอก. สำหรับทดลองดีไซน์และขั้นตอนการทำงาน ก่อนพัฒนาระบบจริงด้วย Vercel + Supabase

Demo: https://oss-client-tracking-demo.surasit76.chatgpt.site

## บัญชีตัวอย่าง

| บัญชี | ชื่อผู้ใช้ | รหัสผ่าน |
|---|---|---|
| Admin | Admin | Admin1234 |
| ลูกค้า | siam | Demo1234 |

ใช้ข้อมูลและรหัสผ่านตัวอย่างเท่านั้น Demo บันทึกข้อมูลในเบราว์เซอร์เดียว และจำลองการ Login/สิทธิ์ผู้ใช้ ยังไม่ใช่ระบบสำหรับเก็บข้อมูลลูกค้าจริง

## หน้าที่มีใน Demo

- แผนที่ความคืบหน้า 15 ขั้นตอน แยกสายโรงงานและ Lab
- Admin เพิ่ม ลบ แก้ไข เปิด/ปิดบัญชีลูกค้า และตั้งรหัสผ่าน
- เพิ่ม/แก้ไขงาน ประเภทคำขอ และมาตรฐานอุตสาหกรรม
- อัปเดตสถานะ วันที่ และหมายเหตุรายขั้นตอน
- ลูกค้าเห็นเฉพาะงานของบริษัทตนเองในมุมมองจำลอง

## เปิดตัวอย่างในเครื่อง

ไฟล์เว็บอยู่ใน `dist/` ใช้เซิร์ฟเวอร์ static ใดก็ได้ เช่น:

```sh
python -m http.server 5173 --directory dist
```

เปิด http://localhost:5173 (ต้องเปิดผ่าน localhost หรือ HTTPS เพื่อใช้ Web Crypto)

## ทดสอบ

ใช้ Node.js 24.15 ขึ้นไป หรือ Node.js 22.22.2 ขึ้นไป:

```sh
npm ci
npm test
npm run test:data
```

การทดสอบฟอร์มครอบคลุมการเพิ่มลูกค้า เปลี่ยนรหัสผ่าน เก็บรหัสผ่านเดิมเมื่อเว้นช่องว่าง ป้องกันชื่อผู้ใช้ซ้ำ และเพิ่ม/แก้ไขงาน จำลองพฤติกรรมของ Chromium ที่ช่องข้อมูลชื่อ `id` บังค่าคุณสมบัติ `form.id` เพื่อป้องกันข้อผิดพลาดเดิมกลับมา

## การพัฒนาระบบจริง

ยังไม่ได้เชื่อม Supabase หรือเผยแพร่ไป Vercel ใน repository นี้ ระบบจริงต้องใช้ Supabase Auth, ฐานข้อมูลร่วม และ Row Level Security โดยการตั้งรหัสผ่านจาก Admin ต้องทำฝั่งเซิร์ฟเวอร์ ห้ามใส่ service-role key ในโค้ดเบราว์เซอร์ ดูรายละเอียดใน [คู่มือ Demo](docs/คู่มือ-Demo.md)

## แก้ไขล่าสุด

- เปลี่ยนคำว่า “สถานี” เป็น “ขั้นตอน” ในหน้าจอทั้งหมด
- แก้ฟอร์มที่บันทึกไม่ทำงาน: ใช้ `getAttribute('id')` แทน `form.id` ซึ่งถูกช่องข้อมูลชื่อ `id` บังในเบราว์เซอร์
- เพิ่มข้อความแจ้งข้อมูลไม่ครบหรือรหัสผ่านสั้นเกินไป และแก้รูปแบบตรวจชื่อผู้ใช้ให้รองรับขีดกลาง
