# คู่มือใช้ AI agent ร่วมกับ OSS Client Portal

## เริ่มด้วยเครื่องมือใดก็ได้

ไฟล์กลางคือ `AGENTS.md` และ `docs/HANDOFF.md` ไม่จำเป็นต้องเข้าถึงประวัติแชตของ Codex เครื่องมือที่ไม่อ่าน `AGENTS.md` อัตโนมัติให้ผู้ใช้แนบไฟล์หรือสั่งอ่านตรง ๆ ก่อนเริ่ม เราไม่ได้ติดตั้งหรือทดสอบ Freebuf, OpenCode หรือ Hermes ในรอบนี้ และไม่ได้รับรองการโหลดไฟล์อัตโนมัติของแต่ละเครื่องมือ

ข้อความเริ่มงานที่ใช้ได้:

```text
ทำงานใน repository OSS_Web อ่าน AGENTS.md, README.md และ docs/HANDOFF.md ก่อน
ตรวจ git status และ branch ปัจจุบัน รักษางานที่มีอยู่ และทำเฉพาะงานต่อไปนี้:
[ระบุงานและผลที่ต้องการ]
ใช้ branch: [ระบุ branch สำหรับงานนี้]
ตรวจผลตามกติกาใน repo แล้วรายงานไฟล์ที่เปลี่ยน ผลการตรวจ และข้อจำกัด
สิทธิ์สำหรับรอบนี้: [เช่น แก้โค้ดและทดสอบ offline; ไม่ deploy หรือแก้ข้อมูลร่วม]
```

ไม่ใส่รหัสผ่านหรือ API key ในข้อความเริ่มงาน ให้เจ้าของตั้งค่าผ่านช่องทางส่วนตัวของเครื่องมือและสภาพแวดล้อมที่ต้องการ

## ตั้งค่าและตรวจโดยไม่แตะข้อมูลร่วม

1. Clone repo หรือใช้ checkout ที่เจ้าของกำหนด ตรวจ `git status --short` และ `git branch --show-current`
2. ใช้ Node.js ตาม README แล้วติดตั้งด้วย `npm ci`
3. `npm test` และ `npm run build` ไม่ต้องใช้บัญชี Supabase จริง ชุด RLS ใช้ PGlite ในเครื่อง
4. หากต้องเปิดเว็บพร้อม API ให้เจ้าของตั้ง `.env.local` ตาม `.env.example` ในเครื่องนี้ แล้วใช้ `npm run dev` ต้องทราบว่าฐานข้อมูลที่เลือกเป็น test หรือ shared ก่อนเขียนข้อมูล

`npm run test:live` ใช้บัญชีในไฟล์ส่วนตัวและเขียน/ลบข้อมูลทดสอบ ไม่เรียกเป็นขั้นตอนเริ่มงานอัตโนมัติ `scripts/bootstrap.mjs` ใช้สร้างระบบในฐานข้อมูลใหม่เท่านั้น ไม่ใช้เพื่อซ่อม Login ในฐานข้อมูลที่ใช้งานอยู่

## หลาย agent ทำงานพร้อมกัน

ให้เจ้าของกำหนดหนึ่งงาน หนึ่ง branch และหนึ่ง checkout/worktree ต่อ agent พร้อมไฟล์ที่รับผิดชอบและเกณฑ์ตรวจ เช่น agent A แก้ UI, agent B แก้ API ใน checkout แยก อย่าให้ทั้งสองเขียนไฟล์เดียวกันในโฟลเดอร์ร่วมพร้อมกัน

ให้ผู้รวมงานตรวจ diff และผลทดสอบก่อน merge หรือ cherry-pick จากนั้นตรวจ flow ที่เชื่อมกันอีกครั้ง branch และ worktree แยกโค้ด แต่ **ไม่ได้แยกฐานข้อมูล**; การทดสอบที่เขียนข้อมูลต้องกำหนด project/test accounts แยกหรือประสานคิวกัน

เอกสารนี้ไม่สร้าง agent ไม่แจก credential และไม่เปิดสิทธิ์ deploy ให้อัตโนมัติ เริ่มจากสิทธิ์ที่จำเป็นกับงานจริง แล้วเพิ่มเมื่อเจ้าของอนุมัติขอบเขตนั้น

## ก่อนเผยแพร่หรือเปลี่ยนฐานข้อมูล

ตรวจ repository, commit, Vercel team/project/environment และ Supabase project ให้ตรงคำสั่งเจ้าของ ค่าที่บันทึกใน HANDOFF เป็นข้อมูลอ้างอิงที่อาจเปลี่ยนได้ ตรวจ migration history ก่อนใช้ไฟล์ใหม่ และเตรียมวิธีกู้คืนตามความเสี่ยงของการเปลี่ยนแปลง

เมื่อได้รับอนุญาตให้อัปเดตเว็บทดสอบเดิม CLI ที่ใช้ครั้งล่าสุดคือ `npx vercel@62.4.0 deploy --prod --yes --scope yoseph6` แม้เว็บใช้ทดสอบ แต่คำสั่งนี้เปลี่ยน **Production alias** `oss-web-eight.vercel.app` จึงไม่ใช้สำหรับงานที่อนุญาตเฉพาะ Preview

## ส่งคืนงาน

รายงาน branch/commit, สิ่งที่เปลี่ยน, ผลตรวจที่รันจริง และสิ่งที่ยังไม่ได้ตรวจ ระบุว่ามีการ deploy หรือ apply migration จริงหรือเพียงเตรียมไฟล์ อัปเดต HANDOFF เมื่อสถานะเปลี่ยน เก็บ credential, session cookies และข้อมูลส่วนตัวไว้ภายนอก repo

สำหรับงาน UI ตรวจ desktop และ mobile พร้อมรูปผลลัพธ์; สำหรับสิทธิ์/ฐานข้อมูลตรวจการแยกข้อมูลและการปฏิเสธสิทธิ์ด้วย รายงาน blocker ที่แท้จริงเพื่อให้ agent ถัดไปทำต่อโดยไม่ต้องเดา
