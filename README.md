# OSS Client Portal

เว็บติดตามงานขออนุญาต มอก. สำหรับลูกค้าแต่ละบริษัท ใช้ Supabase Auth และฐานข้อมูลร่วม พร้อมแผนที่ความคืบหน้า 15 ขั้นตอน แยกโรงงานและ Lab ก่อนรวมสายรับใบอนุญาต

## การใช้งาน

- ลูกค้าเข้าสู่ระบบด้วยชื่อผู้ใช้ที่ Admin กำหนด และเห็นเฉพาะงานของบริษัทตัวเอง
- Admin เพิ่มและแก้ไขบัญชีลูกค้า ตั้งรหัสผ่านใหม่ เปิด/ปิดบัญชี และนำบัญชีออกจากรายการ
- Admin เพิ่มงาน และอัปเดตสถานะ วันที่ และหมายเหตุรายขั้นตอน
- สถานะยังไม่เริ่มและรออยู่เป็นสีเทา สถานะกำลังทำและเสร็จแล้วใช้สีตามเส้นทาง
- หน้าลูกค้าอ่านข้อมูลล่าสุดทุก 30 วินาทีหรือเมื่อกลับมาที่หน้าเว็บ โดยไม่ขัดจังหวะฟอร์มที่กำลังกรอก

ระบบจริงไม่เก็บรหัสผ่านที่เรียกดูได้ Admin ตั้งรหัสใหม่ให้ลูกค้าได้ แต่ดูรหัสผ่านเดิมไม่ได้ รหัสผ่านใหม่ของลูกค้าต้องมีอย่างน้อย 12 ตัวอักษร

## โครงสร้าง

- `src/`: หน้าจอ Vite และแผนที่ขั้นตอน
- `api/portal.js`, `server/`: API ของ Vercel, cookie session, การตรวจสิทธิ์ และการจัดการบัญชีฝั่งเซิร์ฟเวอร์
- `supabase/migrations/`: ตาราง, RLS, และตัวสร้าง 15 ขั้นตอนเมื่อเพิ่มงาน
- `tests/`: ทดสอบสิทธิ์ ฟอร์ม และนโยบายข้อมูลด้วย PostgreSQL ผ่าน PGlite
- `dist/`: Demo Sites รุ่นเดิม เก็บไว้เป็นข้อมูลอ้างอิง ไม่ใช่ไฟล์ build ของระบบจริง
- `build/`: ผล build ของระบบจริง ไม่ commit

## เปิดในเครื่อง

ใช้ Node.js 24.15 ขึ้นไป หรือ 22.22.2 ขึ้นไป

```sh
npm ci
```

คัดลอก `.env.example` เป็น `.env.local` และเติมค่าจาก Supabase โปรเจกต์ที่ต้องการ คีย์ทั้งสามใช้เฉพาะเซิร์ฟเวอร์ ห้ามตั้งชื่อขึ้นต้นด้วย `VITE_` หรือใส่ในโค้ดหน้าเว็บ

```sh
npm run dev
```

เปิด `http://127.0.0.1:5173` API จะทำงานที่ port 3001

## การตั้งค่าฐานข้อมูลครั้งแรก

ใช้ migration `supabase/migrations/20261006160840_oss_portal.sql` กับโปรเจกต์ใหม่ที่ยังไม่มีตาราง OSS จากนั้นสร้างบัญชีเริ่มต้น:

```sh
node --env-file=.env.local scripts/bootstrap.mjs
```

คำสั่งนี้สร้าง Admin และลูกค้าทดสอบสองรายพร้อมงานตัวอย่าง ใช้รหัสผ่านสุ่ม และบันทึกข้อมูลเข้าใช้ไว้ใน `outputs/initial-access.txt` และ `outputs/initial-access.json` ซึ่งไม่ขึ้น Git ห้ามเรียกซ้ำบนฐานข้อมูลที่ใช้งานแล้ว สคริปต์จะหยุดเพื่อรักษาบัญชีเดิม

ชื่อผู้ใช้ถูกแปลงเป็นอีเมลภายใน `<username>@oss-portal.invalid` สำหรับ Auth ส่วนอีเมลติดต่อจริงเก็บแยกในโปรไฟล์ การกู้รหัสผ่านให้ Admin ตั้งใหม่ ไม่ใช้การส่งอีเมลไปที่ที่อยู่ภายในนี้

## ทดสอบ

```sh
npm test
npm run build
```

เมื่อตั้งค่า `.env.local` และบัญชีเริ่มต้นในฐานข้อมูลทดสอบแล้ว:

```sh
npm run test:live
```

การตรวจระบบจริงครอบคลุม cookie session, แยกข้อมูลลูกค้าสองราย, บันทึกขั้นตอน, เพิ่มบัญชี, เปลี่ยนชื่อผู้ใช้และรหัสผ่าน, ปิดบัญชี, นำบัญชีออก และ logout สคริปต์สร้างบัญชีชั่วคราวเพื่อตรวจสอบและลบทิ้งเมื่อจบ ใช้กับฐานข้อมูลทดสอบเท่านั้น

Demo รุ่นเดิมยังทดสอบได้ด้วย `npm run test:demo` และ `npm run test:data`

## เผยแพร่บน Vercel

ตั้งค่า `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SECRET_KEY` เป็น Environment Variables ใน Vercel ทั้ง Preview และ Production ที่ต้องการใช้งาน framework เป็น Vite ผล build อยู่ใน `build/` และ API เป็น Node.js Functions ใน Singapore

โครงการนี้เชื่อมกับ GitHub `Seikomura/OSS_Web` และโปรเจกต์ Vercel `oss-web` อย่านำข้อมูลเข้าใช้ใน `outputs/` หรือ `.env.local` ขึ้น repository

การนำบัญชี/งานออกจากหน้าจอใช้การเก็บเข้าประวัติด้วย `archived_at` เพื่อรักษาข้อมูล และบัญชีที่ปิดหรือเก็บเข้าประวัติจะหมดสิทธิ์อ่านข้อมูลทันที ดู [คู่มือระบบจริง](docs/คู่มือ-ระบบจริง.md) สำหรับข้อจำกัดและการส่งต่อ
